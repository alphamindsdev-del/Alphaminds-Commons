## 0. Guiding Principles

The AlphaMinds Commons frontend is a Progressive Web App (PWA). It installs from the
browser. It works offline (shell + cached content). It receives push notifications.
It loads in under 2.5 seconds on a mid-range Android device on a 3G connection.

These are not aspirational. They are the engineering contract. Every decision in this
document serves one of these outcomes.

**The app must not look like Facebook.** The visual identity is: calm, welcoming,
hopeful, human, playful, premium. Each of the Five Houses has its own visual identity
within the shared design system. The app should feel like entering a modern digital
community center, not scrolling a feed.

## 1. Technology Stack

```
Framework:        React 18 + Vite 5
Language:         TypeScript (strict mode)

State:            Zustand (global state), TanStack Query (server state + caching)

PWA:              vite-plugin-pwa (Workbox-powered service worker)
HTTP Client:      Fetch API (native, thin wrapper for auth + error handling)

Icons:            Lucide React (tree-shakeable, edge-native)
Deployment:       Cloudflare Pages (auto-deploy from GitHub main)
UI Generation:    Lovable.dev → export → production hardening (see §10)
```

## 2. Performance Budget

| Metric | Target | Measurement Device |
|---|---|---|
| LCP (Largest Contentful Paint) | < 2.5s | Mid-range Android, 3G (Moto G4 equivalent) |
| FID (First Input Delay) | < 100ms | Same |
| CLS (Cumulative Layout Shift) | < 0.1 | Same |
| Initial JS bundle (gzipped) | < 150KB | Chrome DevTools |
| Time to Interactive | < 3.5s | Lighthouse, 3G throttle |
| API response render | < 200ms after response | TanStack Query stale-while-revalidate |

**Bundle enforcement:** `vite-bundle-visualizer` runs on every build in CI.
If any individual route chunk exceeds 100KB gzipped, the build fails with a
bundle size error. This is non-negotiable. The PWA on a 3G connection cannot
afford to download a fat bundle every route transition.

### 6.2 Service Worker Strategy

```
STRATEGY BY RESOURCE TYPE:

App Shell (HTML, JS chunks, CSS, fonts):
  → Cache Strategy: StaleWhileRevalidate
  → Cache Name: alphaminds-shell-v{BUILD_HASH}
  → Behavior: Serve cached immediately, update in background.
    On next visit after update, new version is active.
  → Expiry: No TTL (content-hashed filenames ensure no stale content)

API Responses — Feed and Lists (posts, events, rooms):
  → Cache Strategy: NetworkFirst with CacheStorageFallback
  → Cache Name: alphaminds-api-feeds
  → TTL: 5 minutes (stale feed is acceptable offline)
  → Behavior: Try network first (200ms timeout), fall back to cache.
    Network errors show cached data with "You're viewing cached content" banner.

API Responses — Daily Content:
  → Cache Strategy: NetworkFirst, NO stale fallback for a different day
  → The service worker checks the cached response's `date` field.
    If cached date != today → show "Connect to see today's Daily" message.
    Never surface yesterday's daily content as today's.

API Responses — Member Profile (my profile):
  → Cache Strategy: StaleWhileRevalidate
  → TTL: 1 hour

Static Assets (R2 images, CDN avatars):
  → Cache Strategy: CacheFirst
  → TTL: 7 days (images don't change often; URL includes content hash for avatars)
  → Max entries: 200 (LRU eviction)

Push Notification Handling:
  → Service worker handles `push` event
  → Parses notification payload: { title, body, url, icon }
  → Shows notification via self.registration.showNotification()
  → `notificationclick` handler: focus existing window or open new one at payload.url
```

### 6.3 Offline Experience

```
Offline states the app must handle gracefully:

1. Full offline (no network):
   → App shell loads from cache
   → Routes with cached data show cached content with offline banner
   → Routes with no cached data show EmptyState with "You're offline" message
   → Post composer is disabled with tooltip "Connect to post"
   → No error pages — always a graceful degraded state

2. Slow network (3G):
   → All list views show SkeletonCard during load (not spinners)
   → Images use lazy loading with blur-up placeholder
   → API calls have a 10-second timeout; show "Taking too long, tap to retry" after

3. Offline → Online transition:
   → Service worker detects connectivity change
   → Sends message to app window: { type: 'ONLINE' }
   → App shows "You're back online" toast
   → TanStack Query automatically invalidates stale queries
```

Every route is code-split. No route loads another route's code.

that route's chunk. This makes tab switches feel instant on 3G.

## 8. Image Optimization

### 8.1 All Images Via Cloudflare Image Resizing

```typescript
// lib/images.ts

type ImageSize = 'avatar_sm' | 'avatar_md' | 'avatar_lg' | 'card' | 'hero';

const IMAGE_SIZES: Record<ImageSize, string> = {
  avatar_sm:  'width=48,height=48,fit=cover,format=auto',
  avatar_md:  'width=96,height=96,fit=cover,format=auto',
  avatar_lg:  'width=192,height=192,fit=cover,format=auto',
  card:       'width=400,format=auto,quality=80',
  hero:       'width=1200,format=auto,quality=85',
};

export function getImageUrl(r2Key: string, size: ImageSize): string {
  const params = IMAGE_SIZES[size];
  return `https://cdn.alphaminds.com/cdn-cgi/image/${params}/${r2Key}`;
}
```

### 8.2 Responsive Images with srcSet

```tsx
// components/common/Avatar.tsx
export function Avatar({ r2Key, displayName }: AvatarProps) {
  if (!r2Key) return <AvatarFallback name={displayName} />;

  return (
    <img
      src={getImageUrl(r2Key, 'avatar_md')}
      srcSet={`
        ${getImageUrl(r2Key, 'avatar_sm')} 48w,
        ${getImageUrl(r2Key, 'avatar_md')} 96w,
        ${getImageUrl(r2Key, 'avatar_lg')} 192w
      `}
      sizes="(max-width: 768px) 48px, 96px"
      alt={displayName}
      loading="lazy"
      decoding="async"
      className="rounded-full object-cover"
    />
  );
}
```

### 8.3 Blur-Up Placeholder

All card images use a blur-up pattern: a tiny (20x20) blurred placeholder is shown
immediately, the full image fades in when loaded. Implemented via CSS transition on
the `img` element's opacity.

## 9. Subscription Tier Gating in the Frontend

**The rule, stated once, never violated:**
Subscription gating is NEVER implemented by hiding DOM elements in React.
The gate is at the Worker. The frontend's only job is to handle the 403 response
and show the upgrade prompt.

```typescript
// lib/api.ts — Fetch wrapper

export interface ApiError {
  error: string;
  code: string;
  upgrade_required?: boolean;
  current_tier?: string;
  required_tier?: string;
}

export class UpgradeRequiredError extends Error {
  constructor(
    public currentTier: string,
    public requiredTier: string
  ) {
    super(`Requires ${requiredTier} subscription`);
  }
}

export async function apiFetch<T>(
  path: string,
  options?: RequestInit
): Promise<T> {
  const token = getSessionToken(); // from secure cookie
  const response = await fetch(`https://api.alphaminds.com/v1${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...options?.headers,
    },
  });

  if (response.status === 403) {
    const body: ApiError = await response.json();
    if (body.upgrade_required) {
      throw new UpgradeRequiredError(body.current_tier!, body.required_tier!);
    }
    throw new Error(body.error);
  }

  if (!response.ok) {
    const body: ApiError = await response.json();
    throw new Error(body.error || `HTTP ${response.status}`);
  }

  return response.json() as Promise<T>;
}
```

```tsx
// In any page or component that calls a tier-gated endpoint:
function RoomDetailPage() {
  const { data, error } = useQuery({
    queryKey: ['room', roomId, 'posts'],
    queryFn: () => apiFetch(`/rooms/${roomId}/posts`),
  });

  if (error instanceof UpgradeRequiredError) {
    return (
      <UpgradePrompt
        currentTier={error.currentTier}
        requiredTier={error.requiredTier}
        featureName="this exclusive room"
      />
    );
  }

  // render normally
}
```


## 10. Lovable.dev → Production Hardening Process

AlphaMinds uses Lovable.dev for rapid UI generation. This is a valid tool in the
workflow, not a shortcut that bypasses quality. Every Lovable output goes through the
following hardening checklist before it is merged to main:

### 10.1 What Lovable Produces

Lovable generates React components with Tailwind classes, basic state, and sometimes
mock data. It does not produce: proper error handling, API integration, auth-aware
components, PWA considerations, or accessibility attributes.

### 10.2 Hardening Checklist (per component/page)

```
AUTH & DATA:
  [ ] Remove all hardcoded mock data
  [ ] Connect to real API via TanStack Query hook
  [ ] Handle loading state with SkeletonCard (not spinner)
  [ ] Handle error state with ErrorBoundary or error UI
  [ ] Handle empty state with EmptyState component
  [ ] Add UpgradeRequired error handling where endpoint is tier-gated

PERFORMANCE:
  [ ] Images use Avatar component or getImageUrl() — no raw src strings
  [ ] Images have loading="lazy" and decoding="async"
  [ ] No inline styles that increase CLS
  [ ] No layout shift on load (fixed heights for skeleton areas)

ACCESSIBILITY:
  [ ] All interactive elements have aria-label or visible label
  [ ] Color contrast meets WCAG AA minimum
  [ ] Form inputs have associated labels
  [ ] Touch targets are ≥ 44x44px

MOBILE:
  [ ] Works on 375px viewport width (iPhone SE)
  [ ] No horizontal scroll
  [ ] Bottom nav is not obscured by page content
  [ ] Keyboard does not obscure form inputs on iOS/Android

SECURITY:
  [ ] No auth token in component code
  [ ] No subscription tier check in component (only UpgradePrompt on 403)
  [ ] No localStorage reads/writes
  [ ] No hardcoded API keys

TAILWIND:
  [ ] Uses design system tokens (house colors, brand colors) not arbitrary values
  [ ] No inline color values (#abc123) — uses CSS custom properties
  [ ] Responsive classes follow the mobile-first pattern (md:, lg: prefixes)

TYPESCRIPT:
  [ ] No `any` types
  [ ] All props interfaces defined
  [ ] API response types imported from packages/types
```

### 10.3 File Naming Convention After Hardening

Lovable output files → rename to PascalCase with descriptive names.
Do not keep Lovable's generated component names if they are generic (e.g., `Component1.tsx`).

## 12. TanStack Query Configuration

```typescript
// lib/queryClient.ts
import { QueryClient } from '@tanstack/react-query';

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime:        5 * 60 * 1000,   // 5 minutes — data is fresh, no re-fetch
      gcTime:           30 * 60 * 1000,  // 30 minutes — keep in memory
      retry:            2,
      retryDelay:       (attempt) => Math.min(1000 * 2 ** attempt, 10000),
      refetchOnWindowFocus: true,         // Refresh when user returns to tab
      networkMode:      'offlineFirst',   // Serve cache even offline
    },
    mutations: {
      retry: 0,                           // Don't retry mutations (prevents double-posts)
      networkMode: 'online',
    },
  },
});
```

## 13. State Management

### Global State (Zustand)

Zustand manages state that lives outside React's component tree:

```typescript
// store/authStore.ts
interface AuthState {
  member: Member | null;
  subscriptionTier: 'free' | 'basic' | 'premium';
  isAuthenticated: boolean;
  setMember: (member: Member) => void;
  clearSession: () => void;
}

// store/notificationStore.ts
interface NotificationState {
  unreadCount: number;
  setUnreadCount: (count: number) => void;
  decrementUnreadCount: () => void;
```

**Rule:** Do not put server data (posts, events, rooms) in Zustand. Those live in
TanStack Query cache. Zustand is only for auth state and UI state that must survive
re-renders without a network request.

## 15. Install Prompt

The PWA install prompt is surfaced naturally, not aggressively.

```typescript
// hooks/usePwaInstall.ts
export function usePwaInstall() {
  const [installPrompt, setInstallPrompt] = useState<BeforeInstallPromptEvent | null>(null);
  const [isInstalled, setIsInstalled] = useState(false);

  useEffect(() => {
    // Capture the browser's install prompt event
    const handler = (e: BeforeInstallPromptEvent) => {
      e.preventDefault();
      setInstallPrompt(e);
    };
    window.addEventListener('beforeinstallprompt', handler);

    // Check if already installed
    if (window.matchMedia('(display-mode: standalone)').matches) {
      setIsInstalled(true);
    }

    return () => window.removeEventListener('beforeinstallprompt', handler);
  }, []);

  const triggerInstall = async () => {
    if (!installPrompt) return;
    const result = await installPrompt.prompt();
    if (result.outcome === 'accepted') setIsInstalled(true);
    setInstallPrompt(null);
  };

  return { canInstall: !!installPrompt && !isInstalled, triggerInstall, isInstalled };
}
```

The install prompt is surfaced:
1. After the member completes their first daily content item (milestone moment)
2. In the Profile page settings as "Add to Home Screen"
3. Never as a popup on first visit — that is hostile UX

## 16. Deployment Pipeline

```
1. Developer pushes feature branch to GitHub
2. Cloudflare Pages creates preview deployment (previews.alphaminds.pages.dev)
3. Preview URL is posted to PR as a comment
4. PR review includes:
   - Visual review of preview deployment on mobile (BrowserStack or personal device)
   - Lighthouse score check (must pass performance budget)
   - Bundle size check (CI job using vite-bundle-visualizer)
5. PR merged to main
6. Cloudflare Pages auto-deploys to production (app.alphaminds.com)
7. Service worker cache is automatically busted (new content hashes)
8. All active sessions continue (KV-backed sessions are unchanged)
9. Members get the new version on next page load (StaleWhileRevalidate)
```

**Zero-downtime deployments:** Because the app is a static PWA on Cloudflare Pages
with a KV-backed API, there is no server restart. Deployments are atomic replacements
of static assets. In-flight API requests complete against the Worker, which is always
running the latest deployed version.
